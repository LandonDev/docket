# Work: tasks

A linked Work workspace's Tasks view, and Done as the owner accepting a thread's work (milestone 25).

## The view

`src/renderer/src/work/tasks/TasksView.tsx`, registered by `tasks/view.ts` as a lazy chunk. It reads the sector's open tasks through work-kit's shared task client (`createLifeosViewsClients` in `work-kit/lifeos`, made in `tasks/client.ts`) on the workspace's LifeOS session, which is narrowed to its sector. The groups are LifeOS's own (`groupTasks` from `work-kit/lifeos/tasks`): the first of Today leads with Start thread, Done, Snooze and Open (under 22rem of presses Open gives way, so they end on the rows' column; the task's menu holds it); then Today, This week, Later and Waiting. The lead's due day reads in lower case after "Due" ("Due yesterday", `dueMidLine`); a row is 32px with one line and 48px with two, so a one-line row sits centred among the rest. A row's due time gives way to Start thread on hover; its menu leads with Start thread. ↑ and ↓ move between the rows across the groups, from anywhere in a row (its tick, its Start thread) to the next row's open control (`moveBetweenRows`, work/rowKeys.ts, the one rule People's and a meeting's page's lists use too); the lead is no row. Under the Waiting heading a row's second line is who it waits on alone ("Sam Ortiz"); elsewhere it reads "Waiting on Sam Ortiz". While a task's link read is out, Start thread's place on the lead and at the sheet's foot holds a bone of its shape (28px, 92px, 6px corners), so Done and Snooze never move when it lands. Open shows the task in full in a sheet (`TaskSheet.tsx`, `tasks:get`). A task asked for from elsewhere (a person's page, Work Search: `openWorkView({view: 'tasks', task})`) opens its sheet each time it is asked, the same task twice included: the view hands `Tasks` one fresh request object a time and clears it once the sheet takes it. A task the open list does not hold (a done or dropped one Work Search found) is read by its id alone and its sheet only reads, the presses' row saying its state as a fact in their place ("Done yesterday", "Done Nov 24" from LifeOS's `completedAt`, "Marked done" with no time kept, or "Dropped": `closedWords`, TaskSheet.tsx); a narrow sheet wraps its presses to a second row rather than run off its edge; the words a task was filed from stand muted, with no rule down their side; the open list stays the source of its own rows, and a sheet opened from the list still closes, quietly, once its task leaves it; the workspace's record keeps the open sheet (`keepPlace`, `{task, byId}`), so a relaunch opens it again, one asked for by id read by id again; a row's tick reaches 8px a side, its press ending where the title starts; New task in the header makes one (`NewTaskDialog.tsx`, `tasks:create`); its dialog is the frame's (`Kept`), so a session that drops while it is open keeps what he typed, says `DownLine` in it and holds Add until the session reads again; with this computer itself offline it says "This computer is offline" (`OfflineLine`) and holds Add, since it writes to LifeOS itself and a link to the box that is down leaves it able (`tasks/offline.ts`). A title or line a row cuts is said whole in the row's one tip, on hover and focus, only while one is cut (Agenda's rule). Done held for a down link, on the lead and in the sheet, stays a Tab stop (`focusableWhenDisabled`, aria-disabled) whose tooltip says the link's words, so the keyboard reaches the reason the sheet covers; a row's held tick says them on hover (`HeldTip`). The column's Tasks row shows the open count (`useOpenCount`, tasks/facts.ts).

Start thread is `startThread(chip)` with `{kind: 'task', label, ref: {at: 'lifeos', table: 'tasks', id}}`: a new thread's composer with the chip in it, and nothing runs until he sends. A task of a LifeOS project opens that composer under the project's mirror (`startFiled`, tasks/startScope.ts; work.md "Threads file into their projects"); a finished project, or one the host could not open, opens it loose in the job with one quiet line. A draft in that scope that holds his words about something else is kept, and the task gets a draft of its own. The first send carries `about`, and the host links the thread to the task (`ctx.links.link`). A task whose link names a thread offers Open thread in Start's place, even before the window holds that thread's meta (an unloaded host's, an archived one): its mark waits for the meta, and Open asks the hosts for it first (`openTaskThread` in tasks/links.ts, `ensureMeta`), so a task never sprouts a second thread. A link whose thread every host answered without (deleted: Delete thread leaves its LifeOS link open) is no link, and the task offers Start again (`useLiveLink`; `everyHostListed` in lib/tcserver/store.ts: each host connected and listed, archived too); while a host cannot answer it stays Open thread, and an Open that finds nothing toasts "Couldn't find the thread" with Start thread on the toast, his press.

## Open a code thread…

A task's menu (a row's and the lead's right-click) and the task sheet's foot offer Open a code thread…, which starts a thread on the task in a code workspace (`tasks/CodeThreadDialog.tsx`, the pure parts in `tasks/codeThread.ts`). The dialog lists the rail's code rows in the rail's order, pinned first, a workspace linked across hosts once, as its first copy on a host with Work on (the lead's when its host has it): a host with Work off refuses a create that carries `about`, so a row with no such copy is left out. A search field above the list narrows it by name; ↑↓ in the field move the pick, and a host's name shows only where two rows share a name. Project shows once the picked workspace has projects (that copy's own, archived ones left out), None by default; a pick the search moves to another workspace drops the project (`pickedProject`). Start calls the view's `startThread(chip, {cwd, projectId})`: `workStartPort` moves the window to that workspace and opens a draft there by project (none for None, never the folder's local project), with the chip in its composer. The chip leads the draft and replaces a LifeOS chip an unsent draft there still held from an earlier start (`startAboutChip`, Start thread's too), so the first send says the thread is about the task just picked. For a workspace that cannot read LifeOS, Start pressed before the task's notes load spins until they do. Nothing runs until he sends; the first send carries `about`, and the host links the thread to the task as Start thread's is linked.

What the thread may read of the task follows the workspace's own LifeOS link, never widened for this: a code workspace linked to the Work workspace's sector (`work.lifeos.link`) reads LifeOS through its own sector key, so its chip is the task's plain chip; any other gets the task's title and notes as text in the chip (`quote`, which `chipLine` writes under the chip's line), and no LifeOS reach. Both chips name the task, so the link is made either way.

The Tasks view names only the pure work-kit modules (`work-kit/lifeos`, `work-kit/lifeos/tasks`, `work-kit/views/lib/*`); the client types come off the maker in `tasks/client.ts`. Naming `work-kit/views` in renderer source, a comment included, brings its Kobra components into `work-kit-sources.css`; the Agenda does, for its Week and Month.

## `work.tasks.done {taskId}` (approve)

Done in the view goes through the host, not straight to LifeOS. `tasks/index.ts` reads the task's links (`workLinks:byEntity`) and its sector (`tasks:get`), and completes it with `tasks:complete {id, reason: 'Accepted the work of "<thread title>"', threadLink}` naming this host's newest linked thread of the task's own sector: a Work thread of that sector, or a code thread opened on the task whose workspace is linked to that sector or to none (`worksIn`); with none, it completes it plainly. A code thread on another host than the Work workspace's is not named. Answers `{threadId, nextId}`. A send that goes still completes the thread's linked tasks through `ctx.links.completeFor` (the hold's own path).

## When a read or link fails

Done needs the workspace’s computer. While its link is down, the task list stays readable and Done waits in the lead row, task menu, sheet, and row tick. The link’s return frees those presses.
